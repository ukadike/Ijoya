# Behavior: <name>

Copy this file per behavior once it is implemented (not before — do not
document behavior that doesn't exist yet). Every field is required by the
project directive's documentation standard; leave a field as `OPEN QUESTION`
rather than guessing.

- **Purpose:** Why this behavior exists — what part of interdependence,
  accessibility, or environmental participation it makes visible.
- **Participating bodies:** Which sculptural bodies are involved, and what
  role each plays (sender, receiver, both).
- **Trigger:** What sensed condition or incoming message starts this
  behavior.
- **Interpretation:** How the triggering body's logic interprets the trigger
  before acting.
- **Transmitted message:** Which message(s) from
  [`behavioral-language.md`](../behavioral-language.md) this behavior sends,
  and to whom.
- **Receiving body:** Which body receives the message and what state
  transition (see [`state-model.md`](../state-model.md)) it undergoes.
- **Physical response:** The actual soft-robotic movement/output produced —
  described in terms a non-engineer can picture (breathing, leaning,
  supporting, recovering, yielding, stretching, waiting).
- **Accessibility impact:** Completed against the checklist in
  [`accessibility.md`](../accessibility.md).
- **Safety considerations:** Force limits, recovery behavior, and any
  visitor groups (children, wheelchair/cane/walker users, guide/service
  animals) that needed specific design attention.
